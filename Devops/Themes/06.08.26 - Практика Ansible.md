## Что делали

- Автоматизировали настройку локального сервера: установку Docker и деплой Nginx в контейнере.
    
- Разбирали и исправляли ошибки в YAML-плейбуках (права доступа, статусы служб, синтаксис путей).
    
- Отработали базовые модули: `file`, `copy`, `service`, `docker_container`.
    

## Рабочий плейбук

YAML

```
---
- name: Setup local server and deploy Nginx container # Название сценария (playbook)
  hosts: all # Выполнение задачи на всех целевых хостах из файла inventory
  become: true # Запуск с правами root для установки пакетов и изменения системных директорий

  tasks: # Список последовательных шагов
    - name: Ensure configuration directory exists # Шаг создания директории под конфиги
      ansible.builtin.file: # Модуль file для управления файлами и каталогами
        path: /etc/nginx_config # Абсолютный путь к создаваемой директории
        state: directory # Указание типа объекта (директория)
        mode: '0755' # Права доступа: чтение и выполнение всем, запись только владельцу

    - name: Copy Nginx configuration file # Шаг передача конфига на сервер
      ansible.builtin.copy: # Модуль copy для копирования файлов
        src: ./nginx.conf # Локальный путь к исходному файлу
        dest: /etc/nginx_config/nginx.conf # Целевой путь сохранения на сервере
        mode: '0644' # Права доступа: чтение всем, запись только владельцу

    - name: Deploy Nginx in Docker container # Шаг развертывания веб-сервера
      community.docker.docker_container: # Модуль управления контейнерами Docker
        name: web_nginx # Уникальное имя контейнера в системе
        image: nginx:latest # Имя и тег используемого образа из Docker Hub
        state: started # Флаг, гарантирующий запущенное состояние контейнера
        restart_policy: always # Автоперезапуск контейнера при сбое или перезагрузке хоста
        published_ports: # Маппинг сетевых портов
          - "80:80" # Проброс порта 80 с хоста на порт 80 внутри контейнера
```

## Главные выводы и ошибки

- **Права доступа и пути:** При ошибках доступа проверять наличие `become: true` и явно задавать `mode` в строковом формате (например, `'0755'`).
    
- **Типичные сбои:** Большинство ошибок возникают из-за опечаток в путях `src`/`dest` и неверных статусов служб.
    
- **Проверка кода:** Генерацию кода от ИИ необходимо аудировать вручную перед запуском, проверяя синтаксис YAML и логику параметров.
